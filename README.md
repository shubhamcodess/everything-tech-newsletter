# Tech Newsletter

A daily, personally-curated tech newsletter, generated by a Claude Code cloud
routine and published via GitHub Pages.

## How it works

1. `scripts/fetch_all.py` pulls fresh articles from ~47 sources (Hacker News,
   Reddit, arXiv, Dev.to, GitHub Trending, TLDR's tech/AI/dev editions, and
   ~35 RSS feeds) — all free, no API keys, defined in `config/sources.json`.
2. Claude (running as a scheduled routine, no human in the loop) filters the
   results to the topics in `config/interests.json`, clusters duplicate
   coverage of the same story, and judges/ranks the best ones — there's no
   scoring formula, Claude does this qualitatively.
3. It writes the digest to `docs/index.html` and pushes it — GitHub Pages
   serves it at a stable URL.
4. It remembers what it already featured (`data/seen.json`) so the same
   story doesn't repeat across days.

Full pipeline detail lives in `CLAUDE.md`. Setup steps are in `SETUP.md`.

## Repo layout

```
config/
  sources.json     source registry: name, fetch method, category, trust
  interests.json   editable topic boundary -- what the digest should cover
  settings.json    articles_per_digest, lookback windows, etc.
scripts/
  fetch_*.py       one fetcher per source type (rss/hn/reddit/arxiv/devto/github_trending)
  fetch_all.py     orchestrator -- runs every source, writes data/raw_latest.json
templates/
  digest.html.template   placeholder structure/style for docs/index.html
data/
  seen.json        memory of recently-featured stories (committed)
docs/
  index.html       the published digest (GitHub Pages source)
CLAUDE.md          instructions the routine follows every run
ROUTINE_PROMPT.md  the prompt text to paste into the routine
SETUP.md           one-time setup steps (repo, Pages, routine, network access)
```

## Editing without touching the routine

- Add/remove topics: `config/interests.json`
- Change article count or lookback windows: `config/settings.json`
- Add/remove a source: `config/sources.json`

All of these are picked up automatically on the next scheduled run.
