Many AI agents, including the cute and cuddly Muse, can access a user's bank account to perform actions on their behalf. This is already a security nightmare, as most banks mandate that humans log in to their own accounts. The problem is compounded when these agents start to buy things or shift money around. The potential for scams and fraud is off the charts.
Banks have tracked agent activity and suggested that they have done things like contact call centers, all without being given specific permission. This has caused institutions like Morgan Stanley, Bank of America, JPMorgan and Wells Fargo to rapidly make changes to contain any risk. Some have blocked third-party agents from accessing their platforms and others have issued restrictions in certain instances. Many are trying to make it so agents only have read access and cannot actually make any changes.
A Chase spokesperson told Axios that customers should not give their usernames and passwords to anyone, and that includes AI agents. CEO Jamie Dimon also warned in a recent earnings call that there could be thousands of rogue agents operating across financial platforms.
There haven't been too many stories of AI-induced financial calamity just yet, but it's worth exercising some prudence before letting these agents run amok in your bank account. That's because it's highly unlikely you'd get your money back if an agent did do something wrong. The banks wouldn't be liable for restitution, as it would be considered a voluntary action on the part of the user. This is according to laws like the US Electronic Fund Transfer Act. It's not fraud if you're the one handing over the keys to AI. In other words, be careful out there.

## [114] Netflix Bridges AWS IAM and Internal Identity with Workload Attestation
InfoQ | full text via InfoQ | ~468 words

Netflix has developed a workload attestation mechanism that allows Apache Spark jobs running on Amazon EMR to exchange their AWS execution identity for a short-lived internal workload identity. The approach bridges AWS IAM with Netflix’s internal Metatron PKI, allowing managed compute workloads to authenticate to internal services without manually injecting credentials.
Dhruv Pratap, Big Data Platform Engineer at Netflix, described the design in a LinkedIn post as
On infrastructure you build yourself, you can bootstrap your own identity however you like.
Netflix operates two identity systems. AWS provides managed workloads with an IAM execution role, while internal services use Metatron, a private PKI that issues short-lived X.509 certificates for mutual TLS. Netflix also uses Data Projects as the ownership and identity boundary for data access. A Spark job running on EMR therefore needs to establish that its AWS identity corresponds to the internal identity associated with its Data Project.
The design maps each Data Project to a dedicated IAM role. Because Netflix expects Data Projects to reach the tens of thousands, these roles are deterministically distributed across a pool of dedicated AWS accounts rather than concentrated in one account.
Netflix workload attestation flow (Source: Netflix Blog Post)
When a job is submitted, Netflix’s control plane validates the request, resolves the Data Project’s IAM role, and creates a signed workload metadata payload identifying the intended workload. The control plane is the only service authorized to create these claims.
The Spark driver uses credentials associated with its execution role to create a pre-signed request to the AWS Security Token Service GetCallerIdentity endpoint. Netflix’s Identity service retrieves the request from AWS STS to determine which IAM role signed it, providing an independently verifiable statement of the workload’s AWS identity.
The Identity service then compares the AWS response with the signed metadata from the control plane. The AWS response proves possession of the expected IAM role, while the signed metadata identifies the intended workload. Their intersection allows the service to issue a Metatron certificate.
