Cloudflare has moved a post-quantum rebuild of GeoKey Manager into closed beta, protecting geographically fenced decryption keys with a hybrid of ML-KEM-768 and X25519 and replacing the attribute-based encryption the service has relied on since 2022. The beta opened on October 23 to existing Data Localization Suite customers, with general availability planned for the first quarter of 2027.
Chetan Agrawal, Arka Nayan and Erik Engstrom describe the redesign as addressing two requirements at once: data sovereignty rules that confine plaintext processing to a region, and harvest-now, decrypt-later attacks in which traffic captured today is decrypted once a quantum computer exists. GeoKey Manager first shipped in 2017 for TLS keys and moved to ciphertext-policy attribute-based encryption in 2022. Cloudflare gives two reasons for dropping that scheme: no production-ready post-quantum variant exists, and customers don't need the large number of regions it was built to express.
In its place, key protection uses HPKE, the hybrid public-key encryption construction defined in RFC 9180, with a key encapsulation mechanism (KEM) combining ML-KEM-768 and X25519, HKDF-SHA-256 and AES-256-GCM. Two kinds of keys replace the policy expressions. Regional root keys are 256-bit symmetric secrets held one per region. Application-specific key pairs are derived from a root for a single service, such as Tunnel or Gateway, and a single epoch, Cloudflare's term for a key generation that rotation advances. The key-management service derives the application key pair and wraps customer private keys under its public component.
(Source: Cloudflare blog)
The two kinds of keys travel different paths: Quicksilver, Cloudflare's globally replicated key-value store, carries wrapped keys and metadata everywhere, while regional root keys move a separate path through the provisioning service, which stores them in Vault. Before an edge server receives a root key, it must clear three checks: TPM hardware identity verification, a lookup in Zinc, Cloudflare's server inventory, that maps the identity to a data center and location, and a decision by the provisioning service about which roots that server may hold.
Authorized servers then load regional root keys into the kernel keyring rather than onto disk. Because that memory is volatile, "a machine restart removes the keys," and the server has to authenticate again. Regional membership refreshes several times a day as the network changes, separately from key rotation and without customer action.
